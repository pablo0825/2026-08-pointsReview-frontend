# 點數審核系統－產品需求規格

- 文件狀態：第一版基準
- 最後更新：2026-08-13
- 決策來源：[需求討論紀錄](../notes/requirements-discussion.md)
- 相關文件：[申請規則](application-rules.md)、[流程與權限](workflows-and-permissions.md)

## 1. 產品目標

建立一套公開申請、指導老師簽署、承辦人審核及公開查詢學生點數的前端系統。系統必須讓四類申請共用一致流程，同時依類型呈現不同欄位、點數規則與附件要求。

第一版核心成果：

1. 學生不登入即可完成申請。
2. 指導老師登入後檢視指定申請並手寫簽名或拒絕。
3. 承辦人檢視全部待審案件、要求補件、核准或不核准。
4. 核准後建立正式點數，公開頁可依受限條件查詢遮罩後結果。
5. 管理員維護帳號、老師、規則與年度申請辦法，但不參與個案審核。

## 3. 使用者與角色

| 使用者 | 登入 | 主要用途 |
| --- | --- | --- |
| 學生／申請人 | 否 | 建立申請、透過限時連結補件 |
| 指導老師 `advisor` | 是 | 查看自己負責的申請、簽名同意或拒絕 |
| 承辦人 `reviewer` | 是 | 共用案件池、補件、核准、不核准 |
| 管理員 `admin` | 是 | 系統、帳號、老師、規則、申請辦法管理及唯讀查詢 |
| 公開訪客 | 否 | 查詢遮罩後學生點數、閱讀年度規則 |

申請人不建立系統帳號。後台三種角色共用 Email／密碼登入頁，登入後依角色與權限導向對應頁面。

## 4. 第一版產品範圍

### 4.1 公開功能

- 依學年度閱讀已發布的年度申請辦法與規則。
- 從 `/apply` 的四個申請類型入口選擇競賽、參與計畫、證照或展覽申請。
- 使用類型專屬五步表單建立單人或多人申請。
- 從公開老師 API 搜尋並選擇指導老師。
- 上傳及分類 PDF、JPEG、PNG 附件。
- 預覽並一次送出完整申請。
- 透過限時補件連結修改原申請並建立新版本。
- 依年級＋班級或至少兩字元關鍵字查詢遮罩後學生點數。

### 4.2 指導老師功能

- 查看自己的待簽與歷史申請。
- 檢視申請人、參與者、類型資料、附件、版本及時間軸。
- 在簽名 Dialog 中手寫簽名並同意目前版本。
- 填寫原因後拒絕申請。

### 4.3 承辦人功能

- 所有承辦人共用全部案件，不認領或分流。
- 依 `under_review` 與 `needs_revision` 分頁查詢工作佇列。
- 比對申請值、有效規則與核定值。
- 要求補件、延長補件期限、核准或最終不核准。
- 查詢歷史案件、附件、簽名、版本與審核時間軸。

### 4.4 管理員功能

- 管理使用者帳號與指導老師。
- 指派目前主任。
- 管理點數規則及年度申請辦法。
- 唯讀查看所有申請、附件、簽名與審核歷史。
- 查詢學生點數流水帳。
- 不得代替承辦人要求補件、核准或不核准。

## 5. 公開申請需求

### 5.1 申請人與參與者

- 每份申請至少一位參與者，且必須且只能指定一位申請人。
- 申請人必須是參與者之一。
- 申請人姓名直接引用被指定參與者的姓名，不重複輸入。
- 申請人額外提供 Email 與電話，用於通知及聯絡。
- 每位參與者提供姓名、學號、年級、班級及申請點數。
- 競賽申請初始不預設申請人，使用者必須明確將一位參與者設為申請人；選定前隱藏 Email 與電話，選定後將「申請人聯絡資料」顯示在該參與者卡片內。
- 競賽申請若未指定申請人便嘗試繼續，須留在參與者資料步驟、顯示「請先選擇一位參與者作為申請人。」並將焦點移至第一個「設為申請人」按鈕。
- 競賽申請選定申請人後不提供取消操作；改選另一位參與者前須確認，確認後清除既有 Email 與電話並移動聯絡資料區塊。
- 學號是學生點數紀錄的主要識別資料；前後端皆須先 trim 再轉成大寫，並以正規化後的值送出、驗證及儲存。
- 同一份申請不得包含正規化後重複的學號。

### 5.2 學年度與學籍

- 學年度是整份申請的共用欄位，在參與者資料步驟只填一次。
- 送件時前端將共用學年度複製到每位參與者。
- `academicYear` 使用民國學年度字串，例如 `"114"`。
- 第一版年級只支援大一至大四、碩一及碩二。
- 班級支援甲班至戊班；碩士生預設甲班但不限制只能選甲班。

### 5.3 分步表單

1. 學生與參與者資料。
2. 類型專屬申請內容與點數。
3. 指導老師。
4. 附件。
5. 確認送出。

表單步驟間切換須保留資料，最後一步才呼叫正式送件 API。第一版資料只保存在 React 記憶體，離開或重新整理前警告，不使用瀏覽器持久儲存。

競賽申請因參與者點數取決於先選定的競賽等級與獎項，前兩步例外採用「競賽內容」後接「參與者資料」；競賽內容步驟先確立有效規則，參與者資料步驟再依該規則顯示固定點數或開放團隊總點數分配。其他申請類型的步驟順序不因本項調整而改變。

## 6. 指導老師選擇

- 使用 `GET /public/advisors` 取得全部目前可選老師。
- 前端本機搜尋姓名、固定職稱文字及系所。
- 顯示格式為「姓名｜職稱｜系所」。
- 送件只傳 `advisorId`。
- `isDirector` 不顯示、不參與搜尋或選擇。
- 補件時 `advisorId` 不可變更；更換老師必須重新申請。

## 7. 附件

- 允許 PDF、JPEG、PNG。
- 每檔最大 5 MB，每份申請最多 10 個附件。
- 不接受 ZIP、RAR 等壓縮檔。
- 每個附件須選擇分類；選擇 `other` 時其他類型名稱必填。
- 附件說明選填。
- 附件與申請一次送出，第一版不提供送件前暫存。
- 附件與簽名皆為私有檔案，只能由具權限 API 讀取。

## 8. 公開點數頁

- 初始不載入任何學生資料。
- 查詢必須同時提供年級與班級，或提供 trim 後至少 2 個字元的姓名／學號關鍵字。
- 學年度預設目前台灣學年度，也能查詢歷史學年度。
- 結果使用後端分頁，預設每頁 20 筆。
- 顯示遮罩後姓名、學號、學年度、年級、班級、四類點數、總點數及更新時間。
- 不顯示完整個資、附件、聯絡資料、簽名、拒絕原因或審核紀錄。

## 9. 通知與期限

- 系統透過 Email 通知送件、老師簽核、補件、核准、拒絕與逾期結果。
- 老師簽核期限為 7 天，於期限前 72、24、4 小時提醒。
- 老師逾期未處理時申請自動拒絕。
- 補件期限預設 7 天，到期前 24 小時提醒；承辦人可在有效期間內延長。

## 10. 非功能需求

- 公開頁採 Mobile First，最低支援 360px。
- 老師完整簽核流程須支援手機。
- 以 WCAG 2.2 AA 為無障礙目標。
- 支援 Chrome、Edge、Firefox、Safari 及 iOS Safari、Android Chrome 最近兩個主要版本。
- 不支援 Internet Explorer。
- API 錯誤不得暴露 SQL、Stack Trace、Token 或內部敏感資訊。
- 點數不得使用 JavaScript 浮點數直接加總或比較。

## 11. 第一版不包含

- 學校 SSO 或學生 Email 驗證。
- 學生帳號、進度查詢頁、自助撤回或草稿功能。
- 老師要求補件或延長簽核期限。
- 承辦人案件認領、指派或系所隔離。
- 管理員個案審核或稽核紀錄查詢頁。
- 核准後點數更正、異動或沖銷 API。
- 延畢、碩三以上及博士生年級。
- Internet Explorer。
- 參與人數規則管理、版本化及公開查詢 API；第一版依申請類型使用固定人數限制。

## 12. 第一版完成條件

- 四種申請能依規則完成送件，錯誤可定位到欄位或清楚呈現業務原因。
- 老師可從 Email 連結登入、檢視正確版本並手寫簽名或拒絕。
- 補件會建立新版本、使舊簽名失效並重新經過老師簽署。
- 承辦人可安全地處理共用案件池，併發操作不會重複核准。
- 核准只寫入符合規則且大於 0 的最終點數。
- 公開點數頁只在符合查詢條件時回傳遮罩後資料。
- 核心規則、主要元件及完整審核流程具備自動化測試。
