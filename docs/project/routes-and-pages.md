# 點數審核系統－路由與頁面設計

- 文件狀態：第一版基準
- 最後更新：2026-08-12
- 相關文件：[產品需求](product-requirements.md)、[流程與權限](workflows-and-permissions.md)

## 1. 路由原則

- 公開頁與後台頁使用同一 React 應用程式及 React Router。
- 路由層只負責身份、角色與頁面邊界；資料所有權及狀態仍由後端驗證。
- 未登入進入受保護頁時導向 `/login`，並只保留站內安全返回路徑。
- 已登入但角色或權限不符時顯示 403 頁。
- 不存在或基於安全理由不可揭露的資源顯示 404 頁。
- `/` 第一版直接導向 `/apply`，不額外建立行銷首頁。
- Production 以根路徑 `/` 部署，不設定子路徑 base path。
- 共用公開導覽列提供「開始申請」前往 `/apply`，以及「申請辦法」前往 `/rules`。

## 3. 公開申請入口

`/apply` 顯示標題「請選擇申請類型」，並提供四個大型申請類型連結：

- 競賽申請
- 參與計畫申請
- 證照申請
- 展覽申請

四個連結分別前往 `/apply/competition`、`/apply/project-participation`、`/apply/certificate` 與 `/apply/exhibition`。入口頁不顯示額外說明、參與人數、最低附件摘要或個別的「查看申請辦法」；完整辦法統一由共用公開導覽列前往 `/rules`。

## 4. 類型專屬五步表單

### 4.1 共用步驟

1. 學生與參與者資料。
2. 申請內容與點數。
3. 指導老師。
4. 附件。
5. 確認送出。

### 4.2 導覽行為

- 頁首顯示目前步驟與總步驟。
- 下一步前驗證目前步驟；錯誤時聚焦第一個錯誤欄位。
- 上一步不清除資料。
- 預覽頁可直接返回指定步驟修改。
- 表單內不能切換申請類型；返回 `/apply` 會觸發資料遺失警告。
- 第一版只使用記憶體狀態，重新整理或離開頁面不恢復草稿。

### 4.3 送件狀態

- 送出時鎖定表單與按鈕，避免重複 request。
- 欄位錯誤返回對應步驟並聚焦欄位。
- 業務錯誤保留所有資料，顯示後端可讀訊息。
- 成功頁顯示申請編號、目前狀態、送件時間及 Email 通知提醒，不顯示老師簽核期限，避免申請人將期限誤解為老師預計簽核時間。

## 5. 年度申請辦法頁

- 初始顯示標題「請選擇申請類型」，以及「競賽申請」、「參與計畫申請」、「證照申請」、「展覽申請」四個大型按鈕；不預選類型，使用者選擇前不發送公開辦法查詢。
- 學年度選擇器預設目前學年度。
- 只顯示後端已發布且可見的內容。
- 長篇 Markdown 提供標題層級、目錄與頁內錨點。
- HTML 必須經過允許清單式清理，連結使用安全屬性。
- 空資料、載入失敗與歷史年度皆有清楚狀態。

## 6. 公開點數頁

- 初始只顯示查詢說明，不發送資料查詢。
- 合法條件為年級＋班級，或至少 2 字元關鍵字。
- 學年度預設目前學年度。
- 桌面使用表格；手機使用學生摘要卡片。
- 顯示遮罩姓名、學號、學籍歸屬、各類點數、總點數及更新時間。
- 分頁與排序由後端執行，Query 反映在 URL，便於返回與分享查詢條件。

## 7. 指導老師路由與頁面

| 路由 | 說明 |
| --- | --- |
| `/advisor/applications/pending` | 待簽列表 |
| `/advisor/applications/pending/:publicId` | 待簽詳情與操作 |
| `/advisor/applications/history` | 歷史列表 |
| `/advisor/applications/history/:publicId` | 歷史詳情唯讀 |

### 7.1 待簽列表

- 顯示申請類型、申請人、申請總點數、送件時間與截止時間。
- 預設依截止時間由近到遠。
- 即將到期使用文字、圖示與顏色共同提示。

### 7.2 待簽詳情

依序顯示狀態／版本／期限、申請人、參與者、類型資料、附件、版本摘要與時間軸。舊版本可查看但不可簽名。

底部操作：

- 「拒絕申請」開啟必填原因的危險操作 Dialog。
- 「簽名並同意」開啟簽名 Dialog。

### 7.3 簽名 Dialog

- 桌面使用大型置中 Modal，手機使用全螢幕 Dialog。
- 顯示申請編號、申請人、版本、用途說明與簽名板。
- 空白簽名不能送出；可清除重簽。
- Dialog 本身即為最終確認，不再疊第二層視窗。
- 送出失敗保留當次筆跡；409 時關閉並重新載入案件。

## 8. 承辦人路由與頁面

| 路由 | 說明 |
| --- | --- |
| `/reviewer/applications/review` | 審核工作區 |
| `/reviewer/applications/review/:publicId` | 審核詳情與操作 |
| `/reviewer/applications/history` | 歷史列表 |
| `/reviewer/applications/history/:publicId` | 歷史詳情唯讀 |

### 8.1 審核工作區

- 「待審核」頁籤查詢 `status=under_review`。
- 「補件中」頁籤查詢 `status=needs_revision`。
- 每個頁籤獨立保存分頁與篩選狀態。
- 待審顯示申請編號、類型、申請人、總點數、老師、簽署時間及更新時間。
- 補件中另顯示原因摘要、補件期限及到期警示。

### 8.2 審核詳情

依序顯示申請摘要、申請人與參與者、類型資料、點數審核、附件、老師簽名、版本時間軸及操作區。

- 桌面左側為申請內容，右側固定「審核與點數」面板。
- 手機使用單欄，操作區位於底部且不遮住內容。
- 核定資料直接在詳情頁編輯，Dialog 只負責單一操作與最終確認。

### 8.3 操作 Dialog

- 要求補件：必填原因，顯示預計期限。
- 延長期限：顯示原期限，選擇新期限並填寫原因。
- 最終不核准：必填原因，提示不可恢復。
- 核准：唯讀摘要核定參與者、總點數、調整及流水帳筆數。

`needs_revision` 只提供延長期限與最終不核准，不提供核准或再次要求補件。

## 10. 共用頁面狀態

每個資料頁至少處理：

- 初始載入骨架。
- 空資料說明及下一步行動。
- 可重試的讀取失敗。
- 401 登入失效。
- 403 權限不足。
- 404 資料不存在或連結失效。
- 409 資料已被其他人處理。
- 429 操作過於頻繁。
- Mutation 進行中、成功與失敗。

## 11. 響應式與無障礙

- 最低寬度 360px；公開頁與老師頁完整支援手機。
- 後台表格在手機改為卡片或精簡欄位。
- 主要觸控目標至少 44 × 44px。
- Dialog 鎖定焦點、支援鍵盤關閉並在關閉後返回觸發按鈕。
- 錯誤摘要、欄位訊息及非同步結果須由螢幕閱讀器讀出。
- 不只以顏色傳達狀態。
