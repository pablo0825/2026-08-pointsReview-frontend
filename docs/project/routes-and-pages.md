# 點數審核系統－路由與頁面設計

- 文件狀態：第一版基準
- 最後更新：2026-08-13
- 相關文件：[產品需求](product-requirements.md)、[流程與權限](workflows-and-permissions.md)

## 1. 路由原則

- 公開頁與後台頁使用同一 React 應用程式及 React Router。
- 路由層只負責身份、角色與頁面邊界；資料所有權及狀態仍由後端驗證。
- 未登入進入受保護頁時導向 `/login`，並只保留站內安全返回路徑。
- 已登入但角色或權限不符時顯示 403 頁。
- 不存在或基於安全理由不可揭露的資源顯示 404 頁。
- `/` 第一版直接導向 `/apply`，不額外建立行銷首頁。
- Production 以根路徑 `/` 部署，不設定子路徑 base path。
- 共用公開導覽列提供「開始申請」前往 `/apply`，以及「申請辦法」前往 `/rules`。

## 3. 公開申請入口

`/apply` 顯示標題「請選擇申請類型」，並提供四個大型申請類型連結：

- 競賽申請
- 參與計畫申請
- 證照申請
- 展覽申請

四個連結分別前往 `/apply/competition`、`/apply/project-participation`、`/apply/certificate` 與 `/apply/exhibition`。入口頁不顯示額外說明、參與人數、最低附件摘要或個別的「查看申請辦法」；完整辦法統一由共用公開導覽列前往 `/rules`。

## 4. 類型專屬五步表單

### 4.1 共用步驟

1. 學生與參與者資料。
2. 申請內容與點數。
3. 指導老師。
4. 附件。
5. 確認送出。

競賽申請的前兩步依資料相依性調整為：

1. 競賽內容。
2. 參與者資料。

「競賽內容」先選擇競賽等級與獎項並填寫名稱、類別與日期，只顯示所選規則的分配摘要，不顯示參與者編輯區。「參與者資料」再填寫參與者與學籍資料，並依已選規則顯示唯讀的 `per_person` 點數或可編輯的 `shared_total` 個別點數。競賽申請初始不預選申請人；每張參與者卡片提供「設為申請人」，選定後按鈕改為「目前申請人」，並在該卡片內展開 Email、電話的「申請人聯絡資料」。其他三個申請類型維持原步驟順序與申請人預設行為。

### 4.2 導覽行為

- 頁首顯示目前步驟與總步驟。
- 下一步前驗證目前步驟；錯誤時聚焦第一個錯誤欄位。
- 競賽申請若尚未指定申請人便按下一步，留在「參與者資料」，於錯誤摘要及參與者區域顯示「請先選擇一位參與者作為申請人。」並捲動、聚焦第一個「設為申請人」按鈕；選定後立即清除該錯誤。
- 競賽申請改選申請人前顯示確認；確認後清除原 Email、電話，聯絡資料區塊移至新申請人的卡片。已選定者不可取消，只能透過指定另一位參與者更換。
- 上一步不清除資料。
- 預覽頁可直接返回指定步驟修改。
- 表單內不能切換申請類型；返回 `/apply` 會觸發資料遺失警告。
- 第一版只使用記憶體狀態，重新整理或離開頁面不恢復草稿。

只載入公開規則或老師清單不算修改表單。使用者輸入資料、增減參與者、選擇老師或加入附件後，才視為有未送出資料。步驟間切換不警告；返回 `/apply`、站內前往其他頁面、瀏覽器上一頁、重新整理或關閉分頁時必須警告。站內警告提供「繼續填寫」與「捨棄並離開」；重新整理或關閉分頁使用瀏覽器內建警告。成功送件後解除警告，結果不確定時仍保留警告與 request 快照。

### 4.3 競賽規則與老師清單

- 進入 `/apply/competition` 時只呼叫一次 `GET /public/competition-point-options`，不帶 Query Parameter；切換選項、步驟、參與者或點數時不重新查詢。
- 規則載入失敗時顯示「暫時無法載入競賽點數規則」；成功回傳空陣列時顯示「目前沒有可申請的競賽點數規則」。兩者都提供「重新載入」並禁止繼續與送件。
- 首次進入指導老師步驟時只呼叫一次 `GET /public/advisors`，返回其他步驟再回來時沿用記憶體資料；姓名、職稱與系所搜尋只在前端執行。
- 老師載入失敗時顯示「暫時無法載入指導老師名單」；成功回傳空陣列時顯示「目前沒有可選擇的指導老師」。兩者都提供「重新載入」並禁止進入下一步。
- 重新載入老師清單後，若原選擇已不在最新名單中，清除選擇並要求重新選擇。

### 4.4 確認送出

競賽確認頁使用唯讀摘要，不提供重複輸入欄位，並包含：

1. 申請人與參與者：學年度、申請人聯絡資料、參與者學籍、申請人標示、個別點數與總點數。
2. 競賽資料：競賽等級及其他名稱、獎項、競賽名稱、類別、日期與分配方式。
3. 指導老師：姓名、職稱與系所。
4. 附件：檔名、大小、分類、其他分類名稱、說明及本機預覽。

每個摘要區塊提供「修改」並返回對應步驟，資料不得清除。第一版不增加確認勾選框；按鈕上方提醒資料與附件送出後將交由所選指導老師簽核，送件按鈕使用「確認送出申請」，處理中顯示「送件中…」並鎖定。

### 4.5 送件狀態

- 送出時鎖定表單與按鈕，避免重複 request。
- 欄位錯誤返回對應步驟並聚焦欄位。
- 業務錯誤保留所有資料，顯示後端可讀訊息。
- Network Error、timeout、連線中斷、未收到明確 Response 或任何 HTTP 5xx 時，顯示「無法確認是否送件成功」，不得宣告成功或失敗。
- 「重新確認送件」沿用原 `Idempotency-Key` 與完全相同的 request 快照；「返回修改資料」丟棄原 Key 與快照，下一次送件視為新的邏輯送件。
- 結果不確定時不自動重試，也不提供容易被誤解為建立新案件的一般「再送一次」操作。
- 未知 4xx 若有非空白後端 `message` 則顯示該訊息，否則顯示「送件資料無法處理，請返回表單確認後再試」；保留資料、不自動重試，返回確認頁並廢棄原 Key，下一次送件產生新 Key。
- 成功頁顯示申請編號、目前狀態、送件時間及 Email 通知提醒，不顯示老師簽核期限，避免申請人將期限誤解為老師預計簽核時間。
- 競賽資料或規則錯誤返回「競賽內容」；參與者、申請人聯絡資料或個別點數錯誤返回「參與者資料」。

## 5. 年度申請辦法頁

- 初始顯示標題「請選擇申請類型」，以及「競賽申請」、「參與計畫申請」、「證照申請」、「展覽申請」四個大型按鈕；不預選類型，使用者選擇前不發送公開辦法查詢。
- 學年度選擇器預設目前學年度。
- 只顯示後端已發布且可見的內容。
- 長篇 Markdown 提供標題層級、目錄與頁內錨點。
- HTML 必須經過允許清單式清理，連結使用安全屬性。
- 空資料、載入失敗與歷史年度皆有清楚狀態。

## 6. 公開點數頁

- 初始只顯示查詢說明，不發送資料查詢。
- 合法條件為年級＋班級，或至少 2 字元關鍵字。
- 學年度預設目前學年度。
- 桌面使用表格；手機使用學生摘要卡片。
- 顯示遮罩姓名、學號、學籍歸屬、各類點數、總點數及更新時間。
- 分頁與排序由後端執行，Query 反映在 URL，便於返回與分享查詢條件。

## 7. 指導老師路由與頁面

| 路由 | 說明 |
| --- | --- |
| `/advisor/applications/pending` | 待簽列表 |
| `/advisor/applications/pending/:publicId` | 待簽詳情與操作 |
| `/advisor/applications/history` | 歷史列表 |
| `/advisor/applications/history/:publicId` | 歷史詳情唯讀 |

### 7.1 待簽列表

- 顯示申請類型、申請人、申請總點數、送件時間與截止時間。
- 預設依截止時間由近到遠。
- 即將到期使用文字、圖示與顏色共同提示。

### 7.2 待簽詳情

依序顯示狀態／版本／期限、申請人、參與者、類型資料、附件、版本摘要與時間軸。舊版本可查看但不可簽名。

底部操作：

- 「拒絕申請」開啟必填原因的危險操作 Dialog。
- 「簽名並同意」開啟簽名 Dialog。

### 7.3 簽名 Dialog

- 桌面使用大型置中 Modal，手機使用全螢幕 Dialog。
- 顯示申請編號、申請人、版本、用途說明與簽名板。
- 空白簽名不能送出；可清除重簽。
- Dialog 本身即為最終確認，不再疊第二層視窗。
- 送出失敗保留當次筆跡；409 時關閉並重新載入案件。

## 8. 承辦人路由與頁面

| 路由 | 說明 |
| --- | --- |
| `/reviewer/applications/review` | 審核工作區 |
| `/reviewer/applications/review/:publicId` | 審核詳情與操作 |
| `/reviewer/applications/history` | 歷史列表 |
| `/reviewer/applications/history/:publicId` | 歷史詳情唯讀 |

### 8.1 審核工作區

- 「待審核」頁籤查詢 `status=under_review`。
- 「補件中」頁籤查詢 `status=needs_revision`。
- 每個頁籤獨立保存分頁與篩選狀態。
- 待審顯示申請編號、類型、申請人、總點數、老師、簽署時間及更新時間。
- 補件中另顯示原因摘要、補件期限及到期警示。

### 8.2 審核詳情

依序顯示申請摘要、申請人與參與者、類型資料、點數審核、附件、老師簽名、版本時間軸及操作區。

- 桌面左側為申請內容，右側固定「審核與點數」面板。
- 手機使用單欄，操作區位於底部且不遮住內容。
- 核定資料直接在詳情頁編輯，Dialog 只負責單一操作與最終確認。

### 8.3 操作 Dialog

- 要求補件：必填原因，顯示預計期限。
- 延長期限：顯示原期限，選擇新期限並填寫原因。
- 最終不核准：必填原因，提示不可恢復。
- 核准：唯讀摘要核定參與者、總點數、調整及流水帳筆數。

`needs_revision` 只提供延長期限與最終不核准，不提供核准或再次要求補件。

## 10. 共用頁面狀態

每個資料頁至少處理：

- 初始載入骨架。
- 空資料說明及下一步行動。
- 可重試的讀取失敗。
- 401 登入失效。
- 403 權限不足。
- 404 資料不存在或連結失效。
- 409 資料已被其他人處理。
- 429 操作過於頻繁。
- Mutation 進行中、成功與失敗。

## 11. 響應式與無障礙

- 最低寬度 360px；公開頁與老師頁完整支援手機。
- 後台表格在手機改為卡片或精簡欄位。
- 主要觸控目標至少 44 × 44px。
- Dialog 鎖定焦點、支援鍵盤關閉並在關閉後返回觸發按鈕。
- 錯誤摘要、欄位訊息及非同步結果須由螢幕閱讀器讀出。
- 不只以顏色傳達狀態。
